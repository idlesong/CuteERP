> 版本：v1.2（2026-11-05 路线调整：核对工作流（3.1/3.2 已交付后）移除，改为**每月对账归档路线**——
> 内部对账单加排产核对段（可与 Excel FIFO 公式对照）、关账归档三件（含对账单）、区间汇总导出
> （FROM/TO 选月）；核心诉求「系统之外保留核对过的 Excel 数据」由每月关账留存的对账单快照满足）
> v1.1：导入预检强化先行；核对排除草稿；支持跨月时间段核对
> 前置：P1–P5 功能、第二阶段（月度工作簿 / 两阶段导入 / 对账单 / 关账归档）已交付
> 原则：同前（**尽量简洁** · 业务优先 · 业界最佳实践）

## 0. 定位与现状

过渡期（预计长期）的真实工作方式：

```
多数同事：在 Excel 上工作（录单 / 改单 / 核对）
个别人：  导入导出，维护 CuteERP 与 Excel 的同步；月底对账、关账、备份
```

现状：六类导入已走两阶段框架（`ImportChecker` 预检干跑 + 错误/警告标注文件 + 导入中心），
但校验口径偏宽松（跨客户兜底报价仅警告、核销行免价格校验、分配一致性未校验），
且核对仍靠「导出当月 → 人工对照」。因此本阶段分两步：

1. **先收紧现有导入预检**（2.6，独立于核对框架，可立即实施）；
2. 再把「Excel ↔ CuteERP」的四个核对场景做成一等公民（差异预览/确认应用）：

| 核对场景 | 问题 | 目标 |
|---|---|---|
| 订单核对 | 导入靠"整体覆盖"，Excel 删行系统不知道；改了哪些字段看不出来 | 差异预览（新增/修改/删除），确认后才应用 |
| 销售订单核对 | 同上；草稿/提交状态在 Excel 里不可见 | **草稿属临时数据，正式核对不参与**；导出仅含已提交行 |
| 发货核对 | 系统多录/漏录无法发现 | 双向差异清单（系统有 Excel 无 / Excel 有系统无） |
| 未交订单核对 | Excel 手工计算未交，口径易漂移 | 系统给出权威未交快照（数量+金额），Excel 只做对照 |

核对范围支持**跨月时间段**：按文件内单据日期自动检测整月区间
（如订单接收日期出现在 3 月与 9 月 → 核对区间 = 3 月 1 日 ~ 9 月 30 日，见 D22）。

## 2. 交付物

### 2.6 导入预检强化（**先做**，独立于核对框架）

六类导入器的唯一性与前置条件校验收紧（全部在 `ImportChecker` 预检中体现，
阻断项进 errors，复核项进 warnings，标注文件逐行回写）：

| 导入器 | 唯一性 | 前置条件 / 校验强化 |
|---|---|---|
| 客户 | 中文名唯一（既有） | 必填校验（既有） |
| 产品 | 通用型号唯一（既有，同文件唯一） | 必填校验（既有） |
| 价格 | **Price_number 同文件唯一（新增，重复 → error）** | 成分合计 = 总价（既有）；同客户+型号+档位：**新价与旧价均在生效期内、且订单数量（档位）一致 → 警告人工复核**（不自动替代旧价，人工处理旧价失效；档位不同视为正常新增不警告） |
| 客户订单 | 客户订单号唯一（既有唯一索引） | **价格匹配强化（D18）**：接收日期 + 客户 + 通用型号 + 含税单价 匹配报价，接收日期须落在价格有效期内；**匹配不到 → error（砍价/不一致单一律阻断，无比例缩放）；无跨客户兜底**；多候选 → warning（取生效日期最新）；**核销行只认数量为负**（标注不再参与识别），价格继承原行快照，仅校验原单存在 + 余额 |
| 六联单 | 六联单号唯一（既有） | 分配订单号存在、数量正确；Σ分配 = 六联单数量（既有）；总分配 ≤ 该订单行余额（既有，严于订单总数底线）；**新增（D19）：六联单行与被分配订单行严格一致——相同客户、相同通用型号、相同价格** |
| 发货单 | **日期 + 六联单号 + 快递号唯一（D20：不合并，多快递 = 不同单）** | 六联单号有效（已建档可匹配）；该六联单累计发货数量 ≤ 六联单数量（既有） |

> 实施注意：
> - D18 严格字面后，砍价单/改价单（单价 ≠ 报价总价）无法导入——须先在 Excel 修正单价
>   或先更新价格档案（requested/approved）再导入；导入器报告直接点名「无匹配报价」
> - 客户/产品为订单链路前置，先「检查」通过再导订单（既有约定）

### 2.0 期初数据核对专项（2025-12 至今，先做）

期初导入后累积了 11 个月的存量数据，一次性全量核对不现实。采用
**「逐月切片核对 + 关账封存」的时间电梯方案**：

- **切片**：核对导出/导入按月过滤（每月一个工作簿，文件小、可独立核对）；
  也支持**跨月区间**（D22：按文件内单据日期自动检测整月区间，或显式 `FROM=`/`TO=`）
- **顺序**：由远及近——2025-12 → 2026-01 → … → 上月；**当月不关账**（在途）
- **闭环**：每月流程 = 导出该月工作簿 → Excel 对照 → 核对导入（预览差异 → 确认应用）
  → `rake cute_erp:audit` 该月无问题 → **关账该月**（锁定 + 归档）
- **为什么由远及近**：未交订单是累计口径，早期月份封存后不再变动，
  之后月份的未交基线自然准确；核对进度即"时间电梯"，封存一个月就少操心一个月
- **进度可视化**：关账与归档页显示 2025-12 起每月状态（未核对 / 已关账）
- **数据量评估**：单月工作簿几十~几百行/表，PostgreSQL 单机毫无压力；
  逐月处理后系统内只保留"已核实"的数据，Excel 侧旧月文件即可归档不再维护

**工具增强（并入 2.6/3.1/3.4 实现）**：
- 核对导出/导入支持 `MONTH=`（单月）与 `FROM=`/`TO=`（跨月区间，整月对齐，D22）
- `audit` 报告按月分组输出（哪个月有问题先修哪个月）
- 关账页月份选择范围自动覆盖 2025-12 起的全部月份

### 2.1 核对导出（带指纹）

- 四张核对表独立导出（一张工作簿，每表一个 sheet，支持单月切片或跨月区间）：
  1. **订单核对**：订单行全量（键列：订单号/通用型号/版本 + 隐藏指纹列：order_line.id、updated_at）
  2. **销售订单核对**：六联单行（键：六联单号/产品 + 行 id、状态列）——
     **仅含已提交行（D21，草稿不导出不核对）**；状态列注明「已提交」
  3. **发货核对**：出库明细（键：shipment_id、六联单号/型号/数量/日期）
  4. **未交订单核对**：截至区间末月的快照（订单行 + 未交数量/金额，只读对照）
- 指纹列用途：导入时精确匹配行与判断"是否真的变了"，避免误更新
- TEMPLATE_VERSION 写入每个 sheet 首行隐藏列
- 金额列带币别口径（本币 + 折 RMB，与对账单口径一致；D9 多币种已落地）

### 2.2 核对导入（两步：预览 → 确认）

- 上传核对工作簿 → 预览（不落库）：
  - 按**文件内单据日期自动检测核对区间**（D22，整月对齐），与系统该区间数据逐行对比，
    生成差异清单：
    - **新增**（Excel 有系统无）→ 将创建
    - **修改**（字段级：数量/单价/交期/备注…）→ 将更新，列出改前→改后
    - **删除**（系统有 Excel 无）→ 按 D15：草稿删、已提交作废标记
    - **冲突**（关账月、已出库数量缩减、余额超限…）→ 阻断行
  - 差异暂存（imports 表存原始文件 sha256 + 解析结果，状态 preview）
- 确认（POST apply，携带批次 id）→ 事务内应用全部非阻断差异 → 状态 applied
- imports 表扩展：sha256、状态（preview/applied/discarded）、diff 摘要（diff 可复用现有 stats jsonb）

### 2.3 对账单整合

- 月度对账单保持客户视角（不拆成分）；增加「核对」入口：进入四张核对表的导出/导入

### 2.4 可靠性加固

- `rake cute_erp:audit`：台账不变量自检并出报告（按月分组）
  - Σ分配量 vs 六联单数量；分配 ≤ 行余额；出货 ≤ 生产数量；
    订单行无孤儿；草稿单不含已出库行；关账月无新增变更
  - 关账动作前置强制跑 audit，失败列出问题（可 `--force` 跳过但记录）
- `rake cute_erp:smoke`：把 tmp/check_*.rb 冒烟套件固化为一键任务（8 个脚本：
  check_p2_pages / p3 / p4 / p5 / ui / ui2 / formula / inline，CI/上线前跑）
- 备份：daily 保留 30 天（已实现）+ 每月**恢复演练清单**（docs，人工季度执行）

### 2.5 易用性

- 一页纸 SOP（docs/sop_monthly.md）：导出当月 → Excel 编辑 → 核对导入（预览/确认）→
  对账单复核 → 关账归档
- 工作台（已有 `admin#workbench` 页面）顶部显示：当月未提交草稿数、最近一次导入时间/结果、
  关账状态提示

## 3. 实现要点

- **2.6 全部复用现有 `ImportChecker` / 导入器结构**：只改各导入器校验逻辑与 warnings/errors
  归类，不动框架；标注文件机制既有（错误/警告均逐行回写）
- 差异计算：以指纹列（行 id + updated_at）与键列（订单号/型号/版本）双层匹配；
  指纹匹配不到 → 视为 Excel 新增行（或手工建的行），照常预览
- **区间检测**：取文件内各表单据日期（接收日期/下单日期/出库日期）的 min/max，
  归整为 月首日 ~ 月末日；无日期行回退显式参数或报错
- 差异暂存复用 imports（stats 存 JSON diff），不新建表
- 预览/确认两个动作都要写操作日志（谁、何时、哪个文件、应用了多少差异）
- 校验口径全部复用现有模型校验与 DemandQuery，不另起炉灶；
  价格匹配统一走 `Price.match_for`（D18 的价格参与匹配在入口处收紧）
- **保持简洁**：能用现有校验/查询对象拼装的，不写新框架；单文件服务即可

## 5. 验收标准（摘要）

- **导入预检强化（3.5）**：
  - 价格文件同号两行 → 预检报错；同档位共存 → 警告且旧价未被改动
  - 客户订单：无报价/单价对不上任何报价（含砍价单）→ 阻断；跨客户报价不再兜底；
    两条同价候选 → 警告（取生效最新）；
    负数量行即识别为核销（无需"冲销"标注），价格继承原行，缺原单/超余额 → 阻断
  - 六联单：分配到不同客户/型号/价格的订单行 → 阻断点名；Σ分配 > 余额 → 阻断
  - 出库单：同天同六联单不同快递号 → 两个独立出库单（不合并）
- 核对导出：四表带指纹列与模板版本；单月与跨月区间均可用；
  重复导出指纹一致（幂等）；销售订单核对不含草稿行
- 核对导入：改 1 行 / 加 1 行 / 删 1 行的文件，预览差异完全正确；确认后应用；
  同文件二次确认被 sha256 拦截；关账月文件被拒绝；
  跨月文件（3 月+9 月单据）自动按 3/1~9/30 区间对比
- 发货核对：系统多录与漏录两种场景都能在差异清单中出现
- audit：人为破坏一条分配（数量超余额）后 audit 报告能点名；修复后转绿
- smoke：一键全绿输出（8 个脚本）
- 期初专项：2025-12 起每月完成「导出→核对→关账」闭环，关账页可见逐月进度
