# CuteERP 第三阶段计划：核对工作流 · Excel 并行深化 · 可靠性加固

> 版本：草案 v0（待评审）
> 前置：P1–P4 功能、第二阶段（月度工作簿 / 幂等导入 / 对账单 / 关账归档）已交付
> 原则：同前（大胆重构 · 业务优先 · 简洁 · 业界最佳实践）

## 0. 定位与现状

过渡期（预计长期）的真实工作方式：

```
多数同事：在 Excel 上工作（录单 / 改单 / 核对）
个别人：  导入导出，维护 CuteERP 与 Excel 的同步；月底对账、关账、备份
```

因此本阶段**不新增业务功能**，围绕四个核对场景把「Excel ↔ CuteERP」的往返做成
**一等公民**，并补齐可靠性/易用性短板：

| 核对场景 | 问题 | 目标 |
|---|---|---|
| 订单核对 | 导入靠"整体覆盖"，Excel 删行系统不知道；改了哪些字段看不出来 | 差异预览（新增/修改/删除），确认后才应用 |
| 销售订单核对 | 同上；草稿/提交状态在 Excel 里不可见 | 状态列随核对导出，差异可确认 |
| 发货核对 | 系统多录/漏录无法发现 | 双向差异清单（系统有 Excel 无 / Excel 有系统无） |
| 未交订单核对 | Excel 手工计算未交，口径易漂移 | 系统给出权威未交快照（数量+金额），Excel 只做对照 |

## 2. 交付物

### 2.1 核对导出（带指纹）
- 四张核对表独立导出（一张工作簿，每表一个 sheet）：
  1. **订单核对**：订单行全量（键列：订单号/通用型号/版本 + 隐藏指纹列：order_line.id、updated_at）
  2. **销售订单核对**：六联单行（键：六联单号/产品 + 行 id、状态列）
  3. **发货核对**：出库明细（键：shipment_id、六联单号/型号/数量/日期）
  4. **未交订单核对**：截至日期快照（订单行 + 未交数量/金额，只读对照）
- 指纹列用途：导入时精确匹配行与判断"是否真的变了"，避免误更新
- TEMPLATE_VERSION 写入每个 sheet 首行隐藏列

### 2.2 核对导入（两步：预览 → 确认）
- 上传核对工作簿 → `ImportsController#preview`：
  - 与系统当前数据逐行对比，生成差异清单：
    - **新增**（Excel 有系统无）→ 将创建
    - **修改**（字段级：数量/单价/交期/备注/状态…）→ 将更新，列出改前→改后
    - **删除**（系统有 Excel 无）→ 按建议决策 D15 处理
    - **冲突**（关账月、已出库数量缩减、余额超限…）→ 阻断行
  - 差异暂存（imports 表存原始文件 sha256 + 解析结果，状态 preview）
- 确认（POST apply，携带批次 id）→ 事务内应用全部非阻断差异 → 状态 applied
- imports 表扩展：sha256、状态（preview/applied/discarded）、diff 摘要

### 2.3 对账单整合四核对段
- 月度对账单页面增加「核对」入口：直接进入四张核对表的导出/导入
- 对账单出货段补充快递号/日期差异标记能力（发货核对结果内嵌）

### 2.4 可靠性加固
- `rake cute_erp:audit`：台账不变量自检并出报告
  - Σ分配量 vs 六联单数量；分配 ≤ 行余额；出货 ≤ 生产数量；
    订单行无孤儿（order 存在）；草稿单不含已出库行；关账月无新增变更
  - 关账动作前置强制跑 audit，失败列出问题（可 `--force` 跳过但记录）
- `rake cute_erp:smoke`：把 tmp/check_*.rb 冒烟套件固化为一键任务（CI/上线前跑）
- 备份：daily 保留 30 天（已实现）+ 每月**恢复演练清单**写入 docs（人工季度执行）

### 2.5 易用性
- 一页纸 SOP（docs/sop_monthly.md）：导出当月 → Excel 编辑 → 核对导入（预览/确认）→
  对账单复核 → 关账归档
- 工作台顶部显示：当月未提交草稿数、最近一次导入时间/结果、关账状态提示

## 3. 实现要点

- 差异计算：以指纹列（行 id + updated_at）与键列（订单号/型号/版本）双层匹配；
  指纹匹配不到 → 视为 Excel 新增行（或手工建的行），照常预览
- 差异暂存复用 imports（stats 存 JSON diff），不新建表
- 预览/确认两个动作都要写操作日志（谁、何时、哪个文件、应用了多少差异）
- 校验口径全部复用现有模型校验与 DemandQuery，不另起炉灶

## 4. 交付顺序

```
3.1 核对导出（指纹四表 + 模板版本）
→ 3.2 核对导入（预览差异 → 确认应用）
→ 3.3 对账单整合 + SOP 一页纸
→ 3.4 audit/smoke rake + 关账前置检查
```

## 5. 验收标准（摘要）

- 核对导出：四表带指纹列与模板版本；重复导出两次指纹一致（幂等）
- 核对导入：改 1 行 / 加 1 行 / 删 1 行的文件，预览差异完全正确；确认后应用；
  同文件二次确认被 sha256 拦截；关账月文件被拒绝
- 发货核对：系统多录与漏录两种场景都能在差异清单中出现
- audit：人为破坏一条分配（数量超余额）后 audit 报告能点名；修复后转绿
- smoke：一键全绿输出
